### T-01 팀 파일 길이 확인 (외부 P0-1 → P1, 일부 수용)
- **§7.4 '팀 파일'에 추가:** 파일을 불러온 뒤 `teamFile`이 있고 `|Math.round(duration·1000) − teamFile.durationMs| > FILE_MATCH_TOLERANCE_MS`이면 아래처럼 한다. 상수는 500이고 SP-1에서 조정한다.
  - **뷰어:** 재생을 막지 않는 배너를 띄운다. "리더 파일(m:ss)과 길이가 달라요(이 파일 m:ss). 팀에서 정한 파일인지 확인해 주세요". 파일을 구하는 방법은 말하지 않는다(§1.4).
  - **에디터 (L520 대체):** 확인 창을 띄운다. "지금 정한 팀 파일(m:ss)과 길이가 달라요(m:ss). 바꿔도 대형 시간과 1-1은 그대로예요. 이 파일로 바꿀까요?"
    - [바꾸기]면 `teamFile`을 갱신한다.
    - [취소]면 고른 파일을 버리고 `teamFile`을 유지한다.
    - 차이가 허용 오차 이하이면 `teamFile`을 바꾸지 않는다. 이름만 다른 경우도 포함된다.
    - `teamFile`이 null이면 지금처럼 기록한다.
  - **한계:** 길이가 같은 다른 편집본은 잡지 못한다.
- **에디터 확인이 함께 필요한 이유:** 리더가 편집본을 바꿀 때 확인 없이 덮어쓰면, 뷰어 경고가 틀린 파일을 '일치'로 통과시킨다.
- **M-08 비고:** "길이 불일치 경고·확인(§7.4)"을 덧붙인다.
- **S-07:** "E4: 길이가 같은 편집본 구분"으로 좁힌다. 대체 수단 칸은 "길이 확인(§7.4)"으로 바꾼다. 이름·크기·지문 비교는 하지 않는다. 전송 중에 이름이 바뀌고 재인코딩되기 때문이다.
- **§8 단위 테스트:**
  - 차이 500이면 경고가 없고, 501이면 경고한다.
  - `teamFile`이 null이면 비교하지 않는다.
  - 에디터에서 차이가 허용 오차 이하이면 `teamFile`이 바뀌지 않는다.
- **비주얼 메모:** ⑥에서 길이(m:ss)를 이름보다 눈에 띄게 보여 준다. 기기마다 이름이 달라질 수 있어서다.

### T-02 대형 끼워 넣기 → Must (외부 P0-2 일부, P1)
- **승격 근거:** 대신할 수단이 비현실적이다. 끼워 넣지 못하면 뒤쪽 대형 전부에서 댄서 전부를 다시 끌어야 한다(댄서 수 × 뒤쪽 대형 수). 편집곡의 버전이 바뀌면 이런 일이 파일럿 중에 거의 확실히 생긴다. 문서 형식은 바뀌지 않는다.
- **M-07과 §7.3 '대형 추가' 규칙:** S = 선택 대형, N = S의 다음 대형으로 둔다.
  1. N이 없으면 지금 규칙(L494–497)을 그대로 쓴다.
  2. N이 있으면 S를 복사하고 새 id를 붙여 S 바로 뒤에 넣는다(X).
     - `E = N.startMs − N.transitionInMs`로 둔다. `E − S.startMs < 2`이면 [+대형]을 끈다.
     - `X.startMs`는 `(S.startMs + E)/2`를 블록 드래그와 같은 스냅(L501)에 붙인 뒤 `[S.startMs + 1, E − 1]`로 클램프한 값이다.
     - 상한을 `E − 1`로 두는 이유: 추가 직후 플레이헤드(L484)가 N의 이동 구간 잠금(L485)에 걸리지 않게 하기 위해서다.
     - `X.transitionInMs`는 템포가 있으면 `min(X.startMs − gridMs(beat(X.startMs) − 2), X.startMs − S.startMs)`, 없으면 `min(1000, X.startMs − S.startMs)`다.
     - N의 값은 바꾸지 않는다. X가 S의 복사본이므로 재생 결과는 추가 전과 같다.
- **§2.3 Could:** '대형 사이 끼워 넣기'를 지운다.
- **§8 경계값:** N.transitionInMs=0, `E − S.startMs`가 1과 2일 때, 템포 있음·없음, 추가 직후 편집 잠금이 없는지.
- **§10 M2 끝나는 조건:** "대형 사이에 끼워 넣을 수 있다"를 넣는다.

### T-03 문서 크기와 좌표 반올림 (외부 P0-4 일부)
- **실측:** 상한 문서(50명 × 200대형)의 PUT 본문은 좌표가 무한소수일 때 최대 932KB다. 1MB의 93%이고, Caddy의 `1MB`는 10^6바이트다. 좌표를 소수 4자리로 반올림하면 약 665KB가 된다.
- **L320:** "상한 문서는 약 0.93MB(좌표 무한소수 기준). 좌표를 소수 4자리로 반올림하므로 약 0.67MB"로 고친다.
- **§7.3 정수화에 추가:** 문서에 쓰는 모든 좌표(스냅 결과, 댄서 추가 위치)는 쓰기 직전에 `Math.round(v*1e4)/1e4`로 만든다.
- **L309 백스테이지 판정:** `x < 1/cols − 1e-4` 또는 `x > 1 − 1/cols + 1e-4`로 바꾼다. 경계선 위는 무대다.
  - 반올림 오차는 최대 5e-5다. 그래서 여유값은 그보다 커야 한다.
  - 1e-6이면 cols가 9, 11, 12, 13, 14, 17, 19, 21일 때 경계 토큰이 백스테이지로 뒤집힌다(실측).
- **§7.3에 추가:** 토큰·블록·핸들을 드래그하는 동안에는 문서를 바꾸지 않는다(화면 상태로만 둔다). 손을 뗄 때 한 번만 바꾼다. 댄서 이름도 확정(blur·Enter)할 때만 반영한다.
- **§8:**
  - 통합 테스트의 최악 문서는 7자 좌표(예: `-0.0417`), 20자 한글 이름, 200자 한글 `teamFile` 이름으로 만든다.
  - 단위 테스트에 "cols=21 경계선 토큰은 무대"를 넣는다.

### T-04 형식 번호 규칙 (외부 P0-5 → P2)
- **§5.5에 추가:** 문서에 필드를 추가할 때는 선택 필드라도 `v`를 올린다.
  - 옛 번들은 L335에 따라 편집을 막으므로 모르는 필드를 지우지 않는다.
  - `v`를 올리지 않으면 옛 번들이 필드를 조용히 지우는 데이터 손실 경로가 생긴다.
- **§5.5에 추가:** `v`를 올리는 릴리스는 두 가지를 테스트와 함께 포함한다.
  1. 프론트 판 올림 함수로, 기기 저장소 항목(`content`, `lastSent`)과 받은 문서를 편집·비교하기 전에 최신 판으로 올린다.
  2. 서버의 '같은 내용 → 200' 판정도 저장본의 판을 올린 뒤 비교한다. 그 릴리스의 마이그레이션으로 행을 올려도 된다.
- **L338:** "대형 이름·메모·색: 선택 필드로 추가하고 `v`를 올린다"로 고친다.
- PUT 응답 형식은 바꾸지 않는다.

### T-07 반복 401: 동작 유지 + 기록 + 테스트 (외부 P0-6, 해법 기각)
- **§7.2.6에 추가:** 토큰을 갱신한 뒤에도 PUT이 401이면 서버 인증 설정 문제(JWKS·알고리즘·iss/aud)일 가능성이 크다.
  - 재로그인으로는 풀리지 않는다. 그래서 E3로 두고 10초마다 갱신·재시도한다. 서버를 고치면 저절로 저장된다.
  - 이때 E3 문구의 '인터넷' 안내는 사실과 다르다.
  - 갱신 요청이 429를 받으면 supabase-js가 세션을 지워 SIGNED_OUT이 될 수 있다.
- **§8 단위 테스트:** "A8 갱신 뒤 재전송은 갱신된 토큰을 싣는다"(가짜 API가 받은 Authorization을 확인). 갱신 전 토큰을 클로저로 잡아 두는 구현 버그가 가장 현실적인 원인이다.

### T-10 보안·운영 한 줄들 (외부 P1)
- **§9.3 `_headers` `/*`:** `Referrer-Policy: strict-origin-when-cross-origin`, `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`.
  - 전체 CSP는 보류한다. eruda가 `unsafe-inline`을 요구하고, 5개 환경을 다시 확인해야 한다.
- **API 헤더:** Spring Security 기본 보안 헤더(Cache-Control 등)를 끄지 않는다. 공개 경로는 `web.ignoring()`이 아니라 `permitAll`로 연다.
- **로그:** Caddy·Tomcat 접근 로그를 켜지 않는다. 켜거나 외부 로그·오류 추적 서비스를 붙이려면 처리방침(접속 기록 L635, 위탁)을 먼저 고치고, `/s/`·`/api/share/` 경로의 토큰을 가린다.
- **§3.2 운영 작업:**
  - Spring 컨테이너 포트는 publish하지 않는다. Caddy가 Docker 네트워크로 접근한다. 포트가 열리면 Caddy에서만 하는 1MB 검사를 우회할 수 있다.
  - Lightsail 방화벽은 IPv4·IPv6 모두 22·80·443만 연다.
  - Docker 로그를 순환한다(`max-size 10m`, `max-file 3`). 배포 끝에 `docker image prune -f`를 실행한다.
  - 이미지는 커밋 SHA로 태그한다. 교체 뒤 `/api/health`가 실패하면 잡을 실패로 끝낸다.
  - 롤백은 이전 SHA를 다시 배포하는 것이다. 단, `v`를 올린 릴리스는 롤백하지 않고 수정 릴리스로 고친다.
  - 운영 keep-alive가 성공하면 healthchecks.io의 두 번째 체크에 핑을 보낸다. 운영이 다운되면 알림이 온다. 파일럿 전에는 주기를 1시간으로 줄인다.

- **L574 E2E 시점:** "develop 배포 후. PR 머지는 막지 않는다. M4부터 release PR은 그 develop 커밋의 스모크가 통과한 뒤에만 머지한다(체크리스트 규칙, 필수 체크 아님)." 스모크는 뷰어를 열기 전에 '저장됨 ✓'을 기다린다.
- **L575 실기기:**
  - "토큰 20개" 대신: 댄서 50명으로 드래그·재생이 끊기지 않는지 본다. 상한 문서(통합 테스트 픽스처 재사용)를 열어 토큰 하나를 옮기고, 저장됨까지 걸린 시간을 기록한다. 기기는 빌린 것 중 가장 오래된 안드로이드다.
  - **M2 안에 끝낸다.** 상한을 낮춰야 한다면, 저장된 문서가 생기기 전이어야 한다.
  - 추가: 현실 크기 문서(20명 × 40대형)로 편집 직후 탭 닫기 → 같은 브라우저로 다시 열기 → 저장됨. keepalive 60KB 한도를 현실 문서도 넘기 때문이다.
- **±50ms 정의 (L575, L674):** 각 측정 시점에서 |화면에 그린 시각 − 들린 시각| ≤ 50ms다.
  - 기준은 기기 내장 스피커 또는 유선이다.
  - 블루투스 이어폰 1종은 같은 방법으로 재서 참고값으로 기록한다(S-17 판단용).
- **§10 M5:**
  - 온보딩은 "리더와 1:1로 첫 안무 입력(조작은 리더가 하고 개발자는 설명만 한다)"으로 쓴다.
  - 끝나는 조건에 추가: 파일럿 관찰 기록을 남기고 이슈로 올린다. 기록할 것은 도움이 필요했던 지점, 개발자가 기기를 만진 순간, 잘못 고른 파일, E2·저장 불가·쓰기 실패 배너 발생과 스크린샷이다.
- **§11:**
  - **SP-1:** 같은 파일을 카톡 동영상(일반·HD)·파일 전송·m4a로 만들었을 때 duration 차이를 잰다. 이 값으로 `FILE_MATCH_TOLERANCE_MS`를 정한다.
  - **SP-5:**
    - 16×8에 댄서 20명, 6×4에 50명을 폰 세로로 추가하고 끌어낸다.
    - 토큰 라벨을 정한다. '이름 앞 2글자'면 기본 이름은 모두 '댄서'로 보이고, 김서연과 김서윤은 둘 다 '김서'가 된다.
    - 저가 안드로이드에서 상한 문서의 A1 쓰기 1회에 걸리는 시간을 잰다. 100ms를 넘으면 이슈로 올린다.

## 2. M0 스파이크 결과 PR 후보 (SP-5 뒤에 결정)

- **댄서 겹침 비켜 놓기:** 바퀴 `k = floor(i/(2·rows))`마다 x를 바깥쪽으로 `k/60` 옮긴다(왼쪽은 −, 오른쪽은 +).
  - 모든 격자 × 50명에서 좌표가 겹치지 않았다.
  - x는 항상 −0.1~1.1 안이었다(최솟값 −0.079).
  - 항상 백스테이지 구역에 있었다.
  - 상한은 낮추지 않는다. 대기열이나 빈 칸 탐색은 만들지 않는다.
- SP-1·SP-5 측정 결과로 정할 것: 허용 오차 상수와 토큰 라벨 규칙.

## 4. M1 셋업 확인 항목

- `sshd -T | grep passwordauthentication`의 결과가 `no`인지 확인한다.
- `unattended-upgrades`가 켜져 있는지 확인한다. 릴리스 때 `/var/run/reboot-required`가 있으면 재부팅한다. 컨테이너는 `restart: unless-stopped`로 둔다.
- Lightsail 방화벽에서 IPv4·IPv6 443을 연다. 기본 규칙에는 없다.
- 스테이징 Caddy에 1.1MB PUT을 보내 **413**이 오는지 확인한다. 502가 나온다는 보고가 있고, 502면 A10으로 가서 무한 재시도한다.
- 스테이징과 운영 모두 실제 Supabase 토큰으로 인증 API를 1회 호출한다. 통합 테스트는 `jwt()`로 검증기를 건너뛰고, `/api/health`는 인증을 거치지 않는다.
- 백업 S3 버킷의 리전이 서울인지 확인한다.

## 5. 기각 (사유)

| 검사 제안 | 사유 |
|---|---|
| 파일 이름·크기 비교, 로컬 파일 지문 | 카톡 동영상 전송은 재인코딩하고 이름을 바꾼다. 그래서 거짓 경고만 생긴다. 큰 파일 해시는 폰 브라우저에서 비싸다 |
| 댄서 삭제·작품 삭제·이름 변경을 Must로 | 데이터는 깨지지 않는다. 새 댄서는 이미 모든 대형의 백스테이지에 있다. 대신할 수단이 현실적이고, 나중에 붙여도 안전하다. 순서는 파일럿 피드백으로 정한다(§2.2) |
| 댄서 상한을 16명으로 | 복구할 수 있다(위 토큰을 끌면 아래 토큰이 드러난다). 비켜 놓기 규칙이면 충분하다 |
| IndexedDB 전환 | 창을 닫는 순간에 '기록 → 전송' 순서를 비동기로는 지킬 수 없다. A1~A13을 다시 열어야 한다. 용량은 최악이 할당량의 37%이고, 현실 문서는 48KB다 |
| 기기 저장소 총량 상한, 로그아웃 때 보관·폐기 선택 | 쓰기 실패 경로가 이미 처리한다. 항목은 미전송일 때만 있다 |
| PUT 응답에 정규화한 문서 반환 | 판 올림 규칙(T-04)으로 충분하다 |
| 두 번째 401에서 재로그인·중단 | 서버 설정 문제라 재로그인으로 안 풀린다. E3가 데이터를 지키고 저절로 복구한다 |
| 별명 강제, 공개 미리보기 기능, 링크 재발급 승격 | 별명은 강제할 방법이 없다. 리더가 링크를 직접 열면 미리보기다. 파일럿 규모에서는 수동 재발급으로 충분하다 |
| 전체 CSP(지금) | eruda와 충돌하고 5개 환경을 다시 확인해야 한다. 파일럿 뒤에 트리아지한다 |
| SSH IP 제한, DB 용량 알림, 디스크 알림 | GitHub 러너는 IP 범위가 넓다. 로그 순환과 prune으로 원인을 없앤다 |
| 제품 지표(무도움 완료율 등) | 파일럿이 4명 안팎이라 비율에 의미가 없다. 분석 도구는 개인정보와 범위를 늘린다. 관찰 기록으로 대신한다 |
| 로그아웃을 `scope: 'local'`로(내부 비평가 제안) | global이어야 빌린 기기에 남은 세션을 내 폰에서 끊을 수 있다. 데이터가 사라지는 경우는 다른 기기가 쓰기 실패 상태일 때뿐이라 매우 드물다 |
| 겹침 없는 0.5칸 교차점 배치 | 열거 규칙이 복잡하다. 교차점 간격이 토큰 지름보다 작아 효과가 없다 |
